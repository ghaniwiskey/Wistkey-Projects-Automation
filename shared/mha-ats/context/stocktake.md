# MHA ATS web: stocktake (FAVE, FAVE(HQ), Follow up, Ad hoc)

Core: `../context.md`. Manual: `../docs/user-manual/06-stocktake-fave.md`, `07-stocktake-adhoc.md`.

## Rules
- FAVE number `FAVE FYaa-bbcc`: aa = FY, bb = agency code (SPF 20, HTA 90), cc = running number per FY. Master Setup triggers FAVE at 0000H of the chosen date.
- Update Result: Sighted Result and HTD Follow-up mandatory; HTD auto-mapped from Sighted Result + Condition; SIGHTED + incorrect location shows New Location. Import defaults to Sighted / Working; template header A1 `LMSAssetID`.
- Approval: VET IC Submit > URO Submit/Reject > UAO Approve/Reject. No HQ AO level on SPF or HTA UAT, so UAO approval is final.

## Observed behavior (UAT)
- FAVE Update Result (VET IC): SIGHTED + WORKING -> HTD "No Further Action", FSSC "Working condition", FAVE Status CLOSED, Location Status CLOSED; SIGHTED, no condition -> "To Dispose (FA5)". SIGHTED + NOT IN USE/OBSOLETE -> only "To Dispose (FA5)" (FSSC "Asset is obsolete, pending demolishment / return to SLA [For L&B only]"); SIGHTED + NOT WORKING -> only "To Repair" (FSSC "Working condition", intended); WORKING also offers "To Transfer to another Unit (STO)" (FSSC "Pending STO transfer"). NOT SIGHTED -> "Not Found, for Investigation" (FSSC "Under investigation"), FAVE Status OPEN, Correct Location disabled; also "Asset Physically Disposed (To Dispose - D2)" ("Asset has been physically disposed") and "Cannot be found after investigation" ("Cannot be found after investigation, FA record to be disposed"). The HTD options are rebuilt a moment after a change: read them with a retry. PENDING clears everything. "The stocktake result is updated."; a single asset pre-loads its values.
- FAVE Assign Stocktaker: "User is required"; confirm "...assigning a stocktaker to this FAVE." -> "The stocktaker has been assigned.". No unassign.
- FAVE approval: Submit "Please confirm that you want to submit this FAVE." (no pre-check) -> "Stocktake FAVE has been submitted.". Reject `#modal_reject`: Reason (Others = OTHER) + Remarks, both required; "Stocktake FAVE has been rejected." returns it one level down. Stage cards (#pnlStatus) keep their last status until that level acts again. Approve: "Stocktake FAVE has been approved."; final: row APPROVED / Unit Approving Officer, no more Submit/Update Result/Assign; Dashboard "Total Stocktake Report (Endorsed)" +1.
- After VET IC submits, VET IC (and UAO) can still Update Result (accepted: mha-spf BUG-003 closed as wont-fix).
- FAVE incorrect location (SPF-039): SIGHTED + Correct Location unticked -> Location Status OPEN and a "New Asset Location" section (Group `#subLocList`, Postal Code, Building/Address by XHR, Block max 10, Level max 3, Room No max 5, Remarks max 200). Submit checks in order: "Group / NPC / Base selection cannot be empty.", "Asset location cannot be empty." (postal code), "You must enter at least one field of Block / Level / Room No / Location Remarks.". Saving raises a RELOCATE assignment (Created By the VET IC officer, Approver Role Logistics Officer 1, SUBMITTED, not auto-approved). LOGS1 Approve ("Assignment has been approved") moves the asset. Afterwards the FAVE row keeps the old location and Location Status OPEN; the result is locked: Correct Location gives "Can't set the location correctly because it has already been approved.", PENDING says updated but changes nothing (accepted: mha-spf BUG-009 closed as wont-fix).
- FAVE Import Working Result (before submitting): Dropzone (`input.dz-hidden-input` on <body>), preview `#tbimport` -> "The import record(s) have been successful.". The asset becomes SIGHTED / WORKING, HTD "No Further Action", FSSC "Working condition", FAVE Status and Location Status CLOSED, exactly like a result saved with Update Result (which then pre-loads it); mha-spf BUG-007 (the import used to clear the result, then saved "Sighted") is fixed. Import Template link gives "Page Not Found" instead of the template (mha-spf BUG-006).
- FAVE(HQ) (Agency Admin): read-only view of the FAVE over all agency cost centres (SPF UAT: 37). The cost centre search filters in the browser and selects the first row it shows (clicking a selected row does nothing). Tabs Overview (FSSC legends a..i: Cost, NBV, Count of FA, open follow-up items; non-PENDING results only), Summary (approval stages + results), Details (Search/Clear only). Overview Export = selected cost centre (StktakeFAVEReport_<stamp>.xlsx: sheets A. Stocktake Report with a Legend column like "a. Sighted - Working condition", B. Assets not in FAL, C. Stocktake (For Endorsement) with blank Ministry/Unit/dates); the Export above the cost centre table = whole FAVE (costCenterId=0, about 3 MB). Dashboard "FAVE Follow Up Status" shows 0 items although Follow up lists the FY24 items (probably current FY only).
- Follow up (FALO/URO/UAO): Close Item wizard Start > Choose Asset > Review > End. Lists OPEN items of approved FAVEs (SPF UAT: FAVE FY24-2001, cost centre 332300, about 220). Ticking moves the row out of the list; Next with none: "Please tick at least one asset to process."; Submit (no reason, no confirmation) -> "Stocktake Follow-up Close" / "1 Asset has been closed." and the item is gone.
- Ad hoc Create: Start (One-Off/Periodic, default Periodic; Manual/Random; Name*; Periodic: Recurrence Type*, Number of Recurrence, Start Date = tomorrow) > Choose Asset > Review > "Ad Hoc Stocktake No. ADST<n> has been created". Errors "Stocktake Name is required", "Please tick at least one asset to process.". CREATED; a one-off becomes SUBMITTED once a result is recorded. Periodic + future start can be cancelled ("Stocktake Ad Hoc has been cancelled."); one-off: "Can't cancel one-off stocktake type." (accepted: mha-spf BUG-002 closed as wont-fix). Cancel reason label empty (mha-spf BUG-001; value OTHER, Remarks required). Assets stay selectable while in another ad hoc stocktake.
- Ad hoc Random (SPF-053/054): Choose Asset has no table, only filters (Asset Category, Assignee LOGS1/FALO, Group / NPC / Base, Status: multi-select select2), Max Asset, Max Group / NPC / Base (empty = no limit) and a Search that draws the assets on the server (GET `StocktakeCreate?handler=GetList...maxLoc=`, slow: a few seconds) and fills Total Number of Assets / Total Group / NPC / Base (`#totalAsset`, `#totalLocation`; reset to 0 on Search). Each Search draws again. Next before a Search or after an empty one: "Please click Search button to ensure there is asset(s) based on filter(s) selected."; no match: "No asset found in randomized locations: <groups>". Without a Status filter RETIRED/DISPOSED assets are drawn too. Review lists the drawn assets (no delete column); the setup details show Asset Selection RANDOM and Max Asset / Max Group. Max Group is exceeded now and then by an asset with no Group / NPC / Base counted as an extra group (mha-spf BUG-016).
- Ad hoc Listing: Update Result (SIGHTED/NOT SIGHTED/PENDING + Remarks) -> "The stocktake has been updated." (reloads to Summary). Assign Stocktaker, no confirmation -> "The stocktaker has been assigned.".

## Quirks and waits
- Row text of a hidden tab has no line breaks, so "Asset ID: <id>" runs into a description that starts with a digit ("9I030 PANIC ALARM SYSTEM"). `StocktakeFormPage.assetIdOf` reads the ID line; HTA's FavePage uses it (`assetIdByLabel`).
- FAVE Details columns shift with approval state (no checkbox column once APPROVED): read cells by header text (`FavePage.detailCell`).

## Test data (found at runtime)
- FAVE: tests open the first FAVE in the list (new FY picked up automatically); fixture `faveTarget` = first non-APPROVED cost centre + its first asset, returned to VET IC first. SPF-027 (@final) approves a cost centre for good but never the last one; ask the user before running it. When cost centres run out, give the account another unit (Agency Admin > User > User Listing > pencil > Unit; add, keep the current one since asset tests use its data). Other User Listing accounts may be used (check LoginBk accepts them; mind one session per account).
- FAVE relocation (SPF-039): first non-approved cost centre with a PENDING asset whose Assignee (LOGS1) is the test account (Details filters), fixture `faveRelocateTarget`. Each run uses one asset up (result locked after approval; accepted, mha-spf BUG-009 wont-fix); skips when none is left.
- Follow up (SPF-041): first item in the Follow up list (FALO). Closing cannot be undone, so each run uses one item up; skips when the list is empty.
- Ad hoc: first asset in Choose Asset; stocktaker = first other name in the Assign list. SPF-053 creates a periodic Random setup (Status AVAILABLE, Max Asset 3; skipped when the unit has 3 or fewer AVAILABLE assets) that the cleanup cancels. Each SPF-022 run leaves a one-off setup "QA auto adhoc ..." (one-offs cannot be cancelled; accepted, mha-spf BUG-002 closed as wont-fix).
